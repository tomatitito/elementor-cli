# pages delete always performs a permanent delete

The pages delete command always calls deletePage(..., true), so every deletion is forced and permanent. The --force flag only skips confirmation instead of controlling hard delete behavior. This is a data-loss bug and the UX/help text are misleading.

Evidence:
- src/commands/pages.ts always passes true to client.deletePage()
- src/services/wordpress-client.ts forwards force to the REST API

## Acceptance Criteria

Non-forced delete sends the page to trash or clearly documents permanent deletion.
Forced delete behavior matches the CLI flag semantics.
Tests cover both confirmation and force paths.
